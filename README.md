# 新兴赛项裁判证据台

本仓库记录该项目已确认的领域对象、事件名称和基础校验方式，便于不同系统交换一致的数据。

## 资料范围

- `contracts/domain.schema.json`：领域事件信封、聚合类型与事件名称。
- `data/sample.json`：一条用于本地联调的中文样例。
- `src/`：事件信封的最小校验代码与争议裁决服务。
- `tests/`：验证样例符合基础约定，并覆盖裁决服务行为。

当前资料覆盖规则版本、裁判回避和设备消息。记录一经接收，标识、发生时间与版本不得原地改写；更正使用新的后继记录。个人、机构及商业敏感信息仅向履行职责所需的调用方开放。

## 争议裁决服务

`src/dispute-service.js` 在事件约定之上提供可执行的复核流程：

- **受理冻结**：受理申诉时冻结所针对的赛段、成绩版本与申诉时限，并固定当时生效的规则版本。
- **证据追加**：证据按来源与采集时间追加；自动规则比对只提出疑点（`DOUBT_RAISED`），不形成结论。
- **回避分配**：分配复核人员时排除与参赛方、原判裁判和设备供应商存在冲突者，筛查结果留痕（`RECUSAL_SCREENED`）。
- **签署裁决**：重大改判（局部重算、撤销赛段）须由不同职责的两名复核人员签署；裁决可维持、局部重算或撤销某个赛段，只生成后继更正版本（`SCORE_CORRECTED`），不改写旧成绩。
- **排名引用**：后续排名发布必须引用生效裁决，否则拒绝发布。
- **迟到证据**：超过冻结时限或裁决后送到的证据只触发再审建议（`RETRIAL_SUGGESTED`），可据此开启再审。
- **内容识别**：重复申诉与离线证据回执按内容指纹识别；编号相同但材料变化时隔离待核。
- **截止任务**：由事件中的冻结时限驱动，服务重启后按原时间继续，不重新计时。
- **溯源**：`traceScore` 可从一条成绩还原规则、设备证据、回避检查、签署记录与后续更正。

配套模块：`src/event-store.js`（内存与 JSONL 文件事件存储）、`src/fingerprint.js`（内容指纹）。

## 测试与构建

测试命令：

```bash
npm test
```

编译或构建命令：

```bash
npm run build
```

这些命令可在单个 Linux 应用容器内执行，不需要另行启动外部服务。
