# 新兴赛项裁判证据台

本仓库记录该项目已确认的领域对象、事件名称和基础校验方式，便于不同系统交换一致的数据。

## 资料范围

- `contracts/domain.schema.json`：领域事件信封、聚合类型与事件名称。
- `data/sample.json`：一条用于本地联调的中文样例。
- `src/`：事件信封的最小校验代码。
- `src/dispute/`：争议裁决服务（见下节）。
- `tests/`：验证样例符合基础约定，并覆盖争议裁决服务行为。

当前资料覆盖规则版本、裁判回避和设备消息。记录一经接收，标识、发生时间与版本不得原地改写；更正使用新的后继记录。个人、机构及商业敏感信息仅向履行职责所需的调用方开放。

## 争议裁决服务

`src/dispute/` 在事件信封之上提供争议裁决能力：

- `service.js`：申诉受理、证据追加、规则比对、复核分配、签署与裁决、排名发布、成绩溯源。
- `store.js`：追加式事件存储（内存 / JSON 文件），并持久化截止任务。
- `rules.js`：自动规则比对，只提出疑点，不下结论。
- `fingerprint.js`：按内容识别重复申诉与离线证据回执。

行为约定：

- 受理申诉时冻结所针对的赛段、成绩版本、当时生效的规则版本与申诉时限；逾期申诉不予受理。
- 证据按来源与采集时间追加；申诉时限后到达的证据不进入在办材料，只触发再审建议。
- 复核人员与参赛方、原判或设备供应商存在冲突时不得分配；重大改判（局部重算、撤销赛段）须由不同职责的两名复核人员签署。
- 局部重算产生新的成绩版本并引用生效裁决，旧成绩保持原样；后续排名发布必须引用生效裁决。
- 重复申诉与离线证据回执按内容识别；编号相同但材料变化的提交隔离待核。
- 截止任务随事件存储持久化，服务重启后按原到期时间继续。
- `traceScore` 可从一条成绩还原规则、设备证据、回避检查、签署与后续更正。

## 测试与构建

测试命令：

```bash
npm test
```

编译或构建命令：

```bash
npm run build
```

这些命令可在单个 Linux 应用容器内执行，不需要另行启动外部服务。
